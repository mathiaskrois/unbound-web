# Unbound promotional website

Independent promotional website for the Unbound app, published at `https://krois.dk/unbound/`. The iPhone/Watch app is a separate repository and is not built or deployed by this website.

## Local preview

Run `npm run preview` from this directory, then open `http://127.0.0.1:8080/unbound/`. It builds `dist/` and serves it at the public `/unbound/` mount with Node, so shared partials and asset versions match production.

## Landing page

`unbound/experience/` is the dedicated product walkthrough, focused on importing your own MP3 files and transferring them to Apple Watch for offline playback with Pro. Its three-step interactive illustration uses sample content and performs no actual file transfer. Both pages share the scroll-driven device scene; the experience page adds `experience.css` and `experience.js`.

The page is static HTML, CSS, and dependency-free JavaScript. `tokens.css` holds the single palette, minimum text sizes (11 px labels, 12 px small print), and motion durations and curves; every page loads it first. `unbound/assets/landing.css` supplies the shared product-page layout; `home.css` refines the homepage with editorial typography and open feature columns. The devices are real-time 3D models rendered with three.js (WebGL): `devices-3d/devices-3d.js` builds an iPhone 16 Pro (titanium body, keys, Camera Control, antenna bands, cover glass) and an Apple Watch Series 10 (aluminium case with rounded flanks, knurled crown, side button, sapphire display, and a plum sport band looping around an invisible wrist) at the hardware's proportions, lit by a studio environment with key and rim lights and soft shadows. The phone shows the Library capture with the branding patch; the watch draws its Now Playing screen live, so the clock and progress keep time. `npm run build` bundles three.js and the models with esbuild into `assets/devices-3d.js` (about 150 KB gzipped) and stamps its URL in `landing.js` with a content hash. `landing.js` loads it on demand and passes it the same poses it writes to the CSS devices; the watch renders in a second pass so it always sits in front of the phone, as in the composition. Browsers without hardware WebGL (including software renderers such as SwiftShader), or a stage that is not ready within 3.5 s, use the CSS devices in `devices.css` instead: stacked-slice titanium and aluminium bodies, glass reflections, and a sport band in CSS 3D. Neither device may carry a `view-transition-name` or opacity, because both flatten CSS 3D; the page transition names the stage, and the phone dims its screen rather than fading. The product background stays minimal. The walkthrough adds `experience.css`; legal/support pages retain `site.css`. The devices use CSS perspective and transforms rather than WebGL or a video. Both story pages include the same device markup from `unbound/partials/device-canvas.html` at build time, and `landing.js` scales the 540×680 stage to its measured scene (`--device-fill` sets the share of the scene height; CSS fallbacks apply without JavaScript). The fit is not done in CSS because Safari 26 resolves `tan(atan2())` with container units to a negative scale. `motion.js` provides fixed-step springs (1/120 s) and a requestAnimationFrame loop that stops when every spring has settled, when the scene is offscreen, or in a background tab, so motion is identical at any refresh rate. `landing.js` follows scroll progress with a spring through three chapter poses: the hero pairing, the phone turning to face the viewer for “All yours”, and the phone turning away to show its titanium side while the watch rises and presents its crown for “Leave your phone”, as an MP3 chip travels from one to the other. Fine pointers add a tilt of a few degrees, reflections slide across both screens, the polished lip’s highlight follows each device’s turn, and the devices swing in from depth after the intro. The stage stays hidden from the first paint (an inline `stage-pending` class, with a 5 s CSS failsafe) until its devices and screen are loaded, then fades in during the entrance, so a reload never shows a half-loaded or jumping device; a restored scroll position is applied before it appears. CSS adds an idle float, a live waveform, and a Now Playing clock with its progress bar; these run only once the pause control exists, pause offscreen or when motion is paused, and are absent under Reduce Motion. Reveals stagger sibling content, the essentials artwork assembles once, and cross-document view transitions glide the device stage between the home and experience pages. Mobile uses a single-column composition with the same choreography.

The system Reduce Motion preference is respected on load and when changed, and visitors can pause motion explicitly. Content and the static CSS device composition work without JavaScript. The Watch player is a CSS illustration based on the app's playback controls, not a captured Watch screenshot. The iPhone uses the Library capture with a small HTML branding overlay to reflect the updated in-app logo. Headers, footers, device previews, and the availability section reference the same transparent logo. The build stamps every local asset URL in the HTML with a hash of the file, so changed files are never served from a stale cache.

Brand assets come from the companion Unbound app repository:

- `Design/Previews/modern-library-dark.png` → `unbound/assets/library-dark.webp` (660px wide, WebP quality 88).
- `Design/Brand/unbound-logo-transparent.png` → `unbound/assets/app-icon.webp` (256px, WebP quality 95), `apple-touch-icon.png` (180px), `favicon-32.png`, and `favicon.ico` (16/32/48px). These exports preserve alpha around the rounded glass tile, with no black exterior matte or CSS corner clipping. Regenerate with `python Scripts/export-brand-assets.py --site ../krois/unbound-web` from the companion app checkout; requires Pillow.

The copy retains prelaunch availability. Replace the coming-soon labels with the confirmed App Store URL when the app is released.

## Homepage entrance

`intro.js` and `intro.css` show a once-per-session Watch-logo entrance. The round `watch-icon.webp` (480 px, for display at up to 240 CSS px) comes from the companion app's Watch AppIcon asset. A 120 Hz fixed-step damped spring handles landing and hover; the in-place transformation preserves velocity while aligning the icon’s inner symbol with the video. Background tabs suspend the animation clock. Entry by pointer, Enter, or Space starts unmuted video in the activation handler; rejected audible playback retries muted. Failures reveal the homepage. Skip, Escape, focus isolation/restoration, reduced motion, anchor links, and the no-JavaScript homepage remain supported. The prompt fades in after 1.5 visible seconds, once the logo has landed; early entry remains available. A decoded video frame starts the 180 ms icon dissolve and 550 ms expansion to full-screen framing. The MP4 starts 0.5 seconds into the original source, with audio trimmed identically. Playback continues during the 0.6-second final fade, starting at media time 4.0 seconds (the original 4.5-second animation endpoint). Portrait touch layouts up to 900 CSS pixels wide rotate the aligned artwork 90° anticlockwise in 350 ms. During the intro, viewport-fit=cover enables edge-to-edge layout; the original viewport setting is restored on completion. Mobile artwork uses 100lvh. Browser-tab framing centers the artwork and controls in the visual viewport, including its offset; standalone mode retains its full-height stage. An oversized black backing, hidden page siblings, and a black root prevent Safari from exposing the homepage beneath its translucent controls. Viewport/theme metadata are restored only after the final fade. The video’s original width fills the large viewport height, accepting cropping on tall phones. Controls stay upright; landscape and desktop playback stay upright. Viewport/orientation changes retarget framing over 350 ms without restarting playback. The standalone prompt uses bold cyan/blue glass lettering.

Refresh the intro stylesheet/script query strings when changing the entrance. Browser tests cover playback failures, early/repeated entry, focus, session bypass, media-time fading, frame-rate consistency, and tab suspension. Playwright's desktop/mobile WebKit profiles are engine tests, not physical iPhone Safari validation.

## Browser checks

```sh
npm ci
npx playwright install chromium webkit
npm test
```

Tests cover Chromium, desktop WebKit, and an iPhone WebKit profile: navigation, public routes, scroll transforms, pause/resume, reduced-motion changes, idle animation updates, responsive overflow, keyboard access, axe WCAG checks, and the no-JavaScript fallback. Test dependencies are development-only.

## Build and publishing

Run `npm ci` and `npm run build`. `dist/` contains only the public website and is mounted at `/unbound/`. Local previews serve the built `dist/` directory at http://127.0.0.1:8080/unbound/. CI only checks that the site builds; run the Playwright suite locally with `npm test` before pushing.

After pushing and verifying a source commit, update only `unbound-web.commit` in sibling `krois-site/releases.json` and push the publishing repo. Its GitHub Pages workflow builds the recorded release. The app repository stays at `/Users/mathiaskroismoller/Git/Unbound/`; this website owns its published assets and requires no app checkout to build.

The extracted history preserves the website changes; hashes changed during extraction. The original shared history and unpublished historical icon commit remain in `mathiaskrois/krois-site`.
